# نظام التصنيفات المقترح للمشروع

يهدف هذا الملف إلى توحيد معنى Labels قبل توسع المجتمع. لا يلزم استخدام كل التصنيفات منذ اليوم الأول.

## 1. نوع المساهمة
- `bug`: مشكلة قابلة لإعادة الظهور.
- `enhancement`: تحسين أو ميزة.
- `documentation`: توثيق.
- `research`: بحث أو مقارنة قبل اتخاذ قرار.
- `design`: تصميم أو UX/UI.
- `non-code`: مساهمة غير برمجية.
- `community`: تنظيم المجتمع والتواصل.

## 2. المجال
- `Arabic`: اللغة العربية.
- `RTL`: دعم الاتجاه من اليمين إلى اليسار.
- `accessibility`: الوصول الرقمي.
- `security`: الأمن.
- `performance`: الأداء.
- `SEO`: محركات البحث.
- `metadata`: البيانات الوصفية.
- `OJS`: منصة OJS.
- `Crossref`: تكامل Crossref.
- `ORCID`: تكامل ORCID.
- `search`: البحث.
- `Tadabbur Index`: فهرس تدبر.
- `AI`: الذكاء الاصطناعي.
- `OCR`: التعرف الضوئي على النصوص.
- `data`: البيانات والمعالجة.

## 3. حالة المهمة
- `needs-triage`: لم تُراجع بعد.
- `needs-specification`: تحتاج تعريفًا أدق قبل التنفيذ.
- `blocked`: متوقفة على اعتماد أو مورد.
- `ready`: جاهزة للتنفيذ.
- `good first issue`: مناسبة لمساهم جديد.
- `help wanted`: نبحث عن مساهم.

## 4. نوع المراجعة
- `technical-review`: مراجعة تقنية.
- `security-review`: مراجعة أمنية.
- `scholarly-review`: مراجعة علمية.
- `Quranic-content-review`: مراجعة متخصصة عند التعامل مع نص أو محتوى قرآني.

## قاعدة مهمة
لا نضع عشرات Labels على Issue واحدة. نستخدم الحد الأدنى الذي يجيب عن ثلاثة أسئلة:
1. ما نوع العمل؟
2. ما المجال؟
3. ما حالته الآن؟

وتُضاف علامة المراجعة الخاصة فقط عند الحاجة.
