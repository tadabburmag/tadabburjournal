Tadabbur Journal OJT Development Workflow

الغرض

هذا المسار هو السياسة المعتمدة لتطوير منصة مجلة تدبر وOJS. يمنع أي تعديل مباشر على Production قبل المرور بالمراحل المحددة أدناه.

الأدوار

- إدارة مجلة تدبر: تحديد الأولويات والاعتماد النهائي.
- OpenAI Codex والمطورون: التحليل والتنفيذ في فروع مستقلة.
- Faisal Wahyudi: مراجعة التطوير.
- Nijam Akbar: مراجعة OJS والتوافق.
- Dede Nugroho: مراجعة الخادم والأمان.
- OJS Themes: التنسيق الفني والنشر المعتمد.

قبل التنفيذ

1. Assessment للقراءة فقط.
2. لا تعديل على Production أو قاعدة البيانات أو OJS Core.
3. مراجعة:
   - إصدار OJS وPHP وقاعدة البيانات والخادم.
   - القالب والتخصيصات.
   - الإضافات وإصداراتها.
   - Advanced Custom Pages.
   - أي تعديل سابق على OJS Core.
   - النسخ الاحتياطي والـRollback.
4. فتح Issue محددة للمشكلة.
5. كتابة نطاق واضح ومعيار قبول قبل البدء.
6. تحديد الملفات أو المكونات التي ستتأثر.

أثناء التنفيذ

1. العمل في Branch مستقل.
2. عدم تعديل OJS Core مباشرة إلا بقرار موثق واستثنائي.
3. تفضيل Plugin أو Theme override أو Extension قابلة للصيانة.
4. الالتزام بالتوثيق الفني المقدم من OJS Themes.
5. تنفيذ التغيير أولًا على Staging فقط.
6. اختبار:
   - الوظيفة.
   - RTL والعربية.
   - الهاتف.
   - الأداء.
   - الأمان.
   - توافق OJS.
   - عدم كسر الإضافات الحالية.
7. فتح Pull Request مع وصف مختصر للتغيير والمخاطر وطريقة الاختبار.
8. مراجعة بشرية مناسبة حسب نوع التغيير.

بعد التنفيذ

1. اعتماد نتائج Staging.
2. مراجعة OJS Themes عند الحاجة.
3. موافقة صريحة من إدارة مجلة تدبر قبل Production.
4. أخذ Backup حديث قبل النشر.
5. نشر التغيير وفق خطة معلنة.
6. فحص ما بعد النشر.
7. تنفيذ Rollback فورًا عند ظهور أثر جوهري غير متوقع.
8. توثيق النتيجة في Issue وPull Request.

ممنوعات

- تعديل Production مباشرة من Codex أو أي متطوع.
- إرسال كلمات المرور أو المفاتيح أو Tokens عبر البريد أو Issues أو Pull Requests.
- رفع قاعدة بيانات Production أو ملفات تحوي أسرارًا إلى GitHub.
- إدخال كود مولد بالذكاء الاصطناعي دون مراجعة.
- دمج تغيير كبير دون Staging واختبار.
- الاعتماد على تعديل OJS Core عندما يوجد بديل قابل للصيانة.

مسار العمل المختصر

Issue
→ Assessment
→ Specification
→ Branch
→ Implementation
→ Pull Request
→ Staging
→ Review
→ Approval
→ Backup
→ Production
→ Verification
→ Close

معيار الجاهزية للإنتاج

لا يعد أي تغيير جاهزًا للإنتاج إلا إذا:
- نجح على Staging.
- تم توثيق الاختبار.
- تمت مراجعة المخاطر.
- توجد طريقة Rollback.
- صدر اعتماد صريح من إدارة المجلة.

Advanced Custom Pages

أي تطوير عبر Advanced Custom Pages يتبع أيضًا الدليل:
docs/ADVANCED_CUSTOM_PAGES_OJT.md

ويشمل ذلك الالتزام ببنية customPages، ووجود index.tpl وindex.json، وضبط العربية على ar وrtl، واختبار الصفحة على Staging قبل أي نشر.

ملاحظة

التوثيق الفني المقدم من OJS Themes هو المرجع التشغيلي للتكامل الحالي، دون تجاوز ضوابط Staging والاعتماد.
